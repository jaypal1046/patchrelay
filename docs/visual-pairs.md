# Visible before/patch app pairs

Seven test cases, two separate installations each. Launcher names are `PR1 Before`, `PR1 Patch`, through `PR7 Before`, `PR7 Patch`. Full case name and package appear inside the app. Existing PatchRelay Demo is a separate package and is not replaced.

Both APKs in each pair contain original code only. The Patch app downloads a signed manifest and DEX from the `visual-tests-v1` GitHub prerelease after pressing its download button. The build script checks APK identities and verifies that no APK DEX contains the `ComplexPatch` implementation descriptor. This is not a comparison of an old APK with a replacement APK already containing the fix.

| Pair | Case | Visible result to check |
| --- | --- | --- |
| PR1 | R8 host | Original greeting versus patched greeting, active patch 0 versus 1. |
| PR2 | R8-processed patch | Same greeting change, with an R8-processed downloaded DEX. |
| PR3 | APK assets | Original JSON stays revision 1; patch reports its JAR asset is absent from DEX. This case is unsupported. |
| PR4 | Private file | Revision 1 versus revision 2. Close/reopen a second time to roll back code: active patch returns to 0 while file stays revision 2. |
| PR5 | Missing dependency | Original app has no Codec; patched operation displays its actual missing-library error. |
| PR6 | New bundled dependency | Original app has no Codec; downloaded patch computes SHA-256 of `hello`. |
| PR7 | Existing dependency upgrade | Original app has Gson 2.8.9; patch requests a 2.10.1 API and displays the actual missing-method error because host version wins. |

## Use on the phone

1. Open the numbered Before app and read its actual result.
2. Open the matching Patch app. Initially it also shows patch 0 and original behavior.
3. Tap **1. Download signed GitHub patch**. Wait for signature verification.
4. Tap **2. Close app, then reopen its icon**, then open that same Patch app again.
5. Read the actual operation output and compare it with the Before app. Unsupported cases display an error/unchanged asset; they are not labelled successful updates.

The close button exits only that app, in response to the button press. No installer is used for patch activation. An unconfirmed file-write patch or failed operation rolls code back after the next close/reopen. Clear the selected Patch app's storage in Android settings to reset a case for repetition; doing this removes only that app's test data.

## Observed phone results

All 14 APKs were installed on the RMX2117 phone on 29 October 2026 and left installed for manual comparison. These observations are separate from the earlier instrumentation checks:

- PR1 Before displayed active patch 0 and `Original logic: hello phone`. PR1 Patch fetched its signed update from GitHub, closed/reopened, and displayed active patch 1 and `Complex Kotlin patch: hello phone`. Its APK installation timestamp stayed unchanged. The first download timed out; retry succeeded.
- PR2 showed the same before/after change using the R8-processed patch, with an unchanged installation timestamp.
- PR3's GitHub patch downloaded and verified, but its post-restart screen check was interrupted when PR4 opened on the phone. No complete visible-result claim is made for PR3.
- PR4–PR7 were installed but not yet verified through this visible UI flow. Their earlier signed-fixture instrumentation results remain documented separately in `complex-patch-tests.md`.

Before/after screenshots and captured UI text for PR1/PR2 are saved locally under `.tools/visual-phone/`. Screenshots are not uploaded to the public repository. The phone was left under the user's control after the interrupted PR3 check.

For an explicitly requested automated visible check, `tools/verify-visual-phone.ps1 -Case r8host -Device SERIAL` opens only the selected pair, reads its native screen, taps its visible download/close buttons, compares actual output, captures screenshots and compares install timestamps. It aborts if another app takes the foreground. Reset the selected Patch app's storage before repeating a completed case.

## Build and hosting

Build with JDK 17 and Android SDK 35:

```powershell
.\gradlew.bat :visual:assembleRelease
.\tools\build-visual.ps1 -AndroidSdk $env:ANDROID_HOME
```

The packaging script needs the signing key matching the checked-in public key and the three DEX artifacts generated by `tools/test-complex.ps1`. It produces 14 APKs, seven app-specific signed manifests, three DEX files and an APK hash/package index under `dist/visual/`. The case matrix is `visual/cases.json`.

GitHub tag `visual-tests-v1` is a prerelease so the original demo's latest-release update URL remains unchanged. All visual hosts are R8-minified and non-debuggable. Before/Patch apps have separate private storage; the baseline is a control installation, not shared app data. These apps demonstrate directly distributed Android patch behavior; they do not establish Play Store compliance.
